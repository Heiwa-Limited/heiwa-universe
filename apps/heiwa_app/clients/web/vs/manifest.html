Heiwa vs Manifest

Different categories, honestly.

Manifest is a sharp smart model router with first-rate self-hosted packaging. Heiwa is a local operator runtime where routing is one capability alongside memory, evidence, subagents, crons, and a REPL. If smart routing is all you need, Manifest is smaller and more focused. If you want one coherent operator surface, Heiwa sits in a different category.

Side by side

Scope and shape

Both ship as software operators install themselves. The split is scope: a router vs a runtime.

Which to pick

Pick the one that matches the job.

No framing tricks. If the problem is "route requests across providers to cut cost," Manifest will likely fit without wrestling. If the problem is "I want one installed surface that holds routing, REPL, memory, evidence, subagents, and crons together," Heiwa is built for that shape.

Pick Manifest if Routing is the product

Cost-aware routing across many providers, clean fallbacks, and a web UI are the top asks.

Pick Heiwa if Operator surface is the product

CLI, REPL, memory, evidence, and orchestration alongside routing belong in one place.

Operator runtime first. Provider internals stay provider-owned.
