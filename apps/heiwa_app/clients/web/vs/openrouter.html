Heiwa vs OpenRouter

Local runtime vs remote gateway.

OpenRouter is a hosted model gateway. Requests route through their servers. Heiwa is a local self-hosted runtime. Prompts, keys, memory, and evidence stay on the operator's machine. OpenRouter can still appear as one optional lane inside Heiwa when it's the right tool for a single task.

Side by side

Where the request goes

The sharpest difference is the path of the prompt. One crosses the internet through a third party. The other doesn't.

Axis Heiwa OpenRouter
Architecture Local-first operator runtime on the operator's machine Cloud proxy between the operator's app and each provider
Where prompts flow Directly to the selected provider or the local model Through OpenRouter's servers on the way to the provider
Where keys live In ~/.heiwa/ on the operator's machine Either on OpenRouter (account-level) or scoped to a client key
Per-call fee None — Heiwa is software, not a toll 5% fee on API calls through the gateway
OAuth subscription reuse First-class via provider CLIs Not applicable (API-key gateway model)
Local models First-class via Ollama Not the product's focus
Operator surface Installed binary, REPL, local cockpit API plus dashboard; operator context lives elsewhere
Source Open (see repo) Proprietary
Complement vs compete Can wrap OpenRouter as one optional API-key lane Stand-alone gateway

Which to pick

These solve different problems.

OpenRouter is useful when the operator wants one API surface for many models and is fine with a hosted proxy in the path. Heiwa is useful when the operator wants the runtime, the memory, and the decision surface on their own machine and treats remote gateways as optional escalation lanes.

Pick OpenRouter if You want a hosted multi-model API

Single HTTP endpoint across many models matters more than local-first posture.

Pick Heiwa if Local-first is non-negotiable

Prompts, evidence, memory, and keys stay on your machine; remote lanes are optional.

Operator runtime first. Provider internals stay provider-owned.
