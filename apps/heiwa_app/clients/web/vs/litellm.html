Heiwa vs LiteLLM

Different layers of the stack.

LiteLLM is a compatibility library and proxy that presents many providers as an OpenAI-format API. It is excellent at what it does. Heiwa is not trying to be a drop-in OpenAI-compatible library. Heiwa is an operator runtime where the operator uses a REPL, a CLI, a local cockpit, memory, evidence, and scheduled routines — with routing as one capability among several.

Side by side

Library vs operator product

These tools sit at different layers. One is a dependency a developer imports. The other is a surface the operator uses.

Axis Heiwa LiteLLM
Shape Installed operator runtime and cockpit Python SDK plus an optional OpenAI-compatible proxy
Primary user Operators using a REPL, CLI, and local cockpit Developers building their own app against a unified LLM API
Surface heiwa binary, REPL, localhost cockpit import litellm or litellm --proxy
Scope beyond routing Memory, evidence, receipts, subagents, crons, approvals Request-time concerns: format translation, retries, cost tracking
OAuth subscription reuse First-class via provider CLIs API-key lane (OpenAI-format translation)
Local models First-class via Ollama Supported via Ollama provider in the SDK
Hosting model Self-hosted runtime on the operator's machine Library; proxy runs wherever the developer deploys it
Complement vs compete Could call LiteLLM as a library inside a custom provider lane Solves a compatibility problem, not an operator-surface problem

Which to pick

Layer first, then decide.

If the task is "give my own Python app one unified LLM API," LiteLLM is the right tool. If the task is "I want one installed operator surface that holds routing, REPL, memory, and orchestration together," that's Heiwa. Using both is reasonable — LiteLLM as a library inside a Heiwa custom provider, for example.

Pick LiteLLM if You're building your own app

You need a provider-agnostic LLM client and don't need an operator surface.

Pick Heiwa if You want the operator surface

REPL, CLI, cockpit, memory, and evidence belong in one installed product.

Operator runtime first. Provider internals stay provider-owned.
