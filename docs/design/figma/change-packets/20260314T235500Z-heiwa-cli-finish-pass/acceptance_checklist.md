# Acceptance Checklist

- Add an operator navigation set separate from public marketing/status pages.
- Confirm the operator app includes seven pages:
  - Connections
  - Mission Control
  - Live Run
  - Approvals
  - Rate Groups
  - Cells
  - History
- Show provider readiness from state, not from direct browser access to local keychains.
- Show mission lifecycle and active cell/tool/model metadata.
- Show approval queue actions inline in the app.
- Show rate reserve and surplus headroom for premium groups.
- Show session summaries and artifacts as durable history, not transient logs.
- Preserve the existing public shell styling language while making operator surfaces feel more utilitarian.
- Do not reintroduce public claims that operator-only surfaces are anonymous or public-safe.
